核心价值与理念

从"人找策略"到"策略找人"

将顶级投资经理的分析框架模型化，通过 AI 提供"千人千面"的个性化资产配置，让专业的投顾服务触手可及。

关键结论：投顾工作不再依赖模型凭一句话给出买卖结论，而是由 LLM 在七大核心工具间进行编排，由客户画像、风险测评、市场预警和适当性规则共同决定推荐范围。

一（续）、投顾 Agent 解决的核心痛点

痛点传统做法本系统的解决方式
① 理财顾问效率低，无法规模化 顾问手动翻阅客户资料、产品手册、合规文件，出一份方案要 2-3 小时，一个顾问最多服务 50 个客户。 投顾 Agent 自动聚合画像 + 产品 + 风险规则，一键生成推荐方案，分钟级出结果，AI 7×24 在线，服务能力不再受人力限制。
② 客户画像静态、滞后、不准确 标签靠人工打，评估一次管一年，和实际行为偏差大；顾问靠记忆了解客户，换了顾问就从头开始。 动态客户画像：规则引擎五阶段管道自动计算，行为校准 + 置信度衰减，画像随客户行为持续演化，任何顾问打开系统就能看到最新画像。
③ 风评与推荐脱节 客户风评做一次就归档，后续推荐不看实际风险承受能力；顾问凭经验判断，合规风险高。 投顾 Agent 推荐前自动检测风评状态 → 画像风险等级 → 产品适当性矩阵，越级购买触发披露确认，贯穿全流程的适当性管控。
④ 画像利用不充分 — 有数据没洞察 CRM 里堆满客户数据，但顾问做推荐时还是靠经验拍脑袋，数据和决策是两张皮。 投顾 Agent 以画像为决策中枢：画像 → 适当性筛选 → 产品推荐 → 资产配置，四步全自动，且每一步都可视可解释。

二、用户画像核心亮点

数据架构

动态多表联查 + Cache-Aside 缓存

画像数据不是静态字段，而是从多个业务表动态计算得出：

  • 跨表联查：一次研判关联 sys_user + fin_customer_profile + fin_risk_assessment + fin_holdings + fin_product + fin_transaction 六张表
  • 动态计算：最高持仓产品类型、近一年交易频率、历史盈亏水平、亏损承受能力均从数据库实时统计
  • Cache-Aside 模式：查询先走 Redis（TTL 7天），未命中则查 MySQL 并回填缓存；画像更新后主动失效缓存

三、七大核心工具详解

我们将投顾所需的核心能力拆分为七个原子化工具，确保每一步推荐都有据可依：

工具名称核心功能数据来源
smart_recommend 一键智能推荐：自动串联风控预警检查 → 风评状态检查 → 画像查询 → 产品推荐 → 资产配置，一次调用完成全链路。 MySQL + Neo4j + Redis
profile_tool 查询客户风险画像：精准获取客户四维度得分、C1-C5风险等级、熔断规则触发情况及警告信息。 MySQL + Redis
recommend_products 产品推荐打分排序：执行严格的漏斗筛选（风险过滤 → 适当性过滤 → 偏好过滤 → 持仓互补），并进行多因子排序输出 TopN。 MySQL
asset_allocation 资产配置建议：根据客户 C1-C5 风险等级，科学给出货币类、债券类、混合类、股票类及现金的比例分配建议。 MySQL
analysis_holdings 持仓综合分析：穿透分析持仓明细、行业集中度、盈亏汇总，并结合 Neo4j 图谱进行深度的行业穿透分析。 MySQL + Neo4j
compare_customers 客户对比分析：支持多维度的客群对比，包括画像差异、共同持仓情况以及行业偏好对比。 MySQL + Neo4j
graphrag_search 知识增强检索：融合 Milvus 向量相似度检索与 Neo4j 图谱多跳查询，为推荐提供深度的知识上下文。 Neo4j + Milvus

四、三大核心工程亮点

亮点一

Neo4j 同步失败自动重试机制

问题背景：知识图谱（Neo4j）数据同步可能因网络抖动失败，导致推荐数据不一致。

解决方案：主业务异步非阻塞，失败时数据快照写入 MySQL 兜底表。后台定时任务（每60秒）采用线性退避策略最多重试10次，若仍失败则标记为人工介入。

业务价值：保证了知识图谱数据的最终一致性，确保推荐质量不受底层同步问题的影响。

亮点二

注册后风评问卷弹窗与默认 R1 推荐

问题背景：用户注册后若无有效风评，直接推荐存在合规风险。

解决方案：前端通过接口判断并弹出问卷；后端在风评完成前，smart_recommend 工具会强制将客户降级为 C1（保守型），仅推荐 R1（低风险）产品，并在回复中明确告知问卷入口。

业务价值：合规优先，严守适当性底线；通过前端弹窗与后端降级双重提醒，主动引导客户完成测评，形成业务闭环。

亮点三

风险等级自动降级机制

问题背景：客户自评风险等级可能与其实际交易行为（如恐慌性赎回）存在偏差。

解决方案：系统通过 BehavioralCalibrator 对比自评与行为画像。当偏差方向一致且达到阈值时，每次最多下调一个风险等级（如 C4 降至 C3），设有7天冷却期，并保留完整审计记录。

业务价值：用客观的交易行为数据纠偏主观的自评画像，有效防范适当性风险，使客户画像更真实可靠。

五、技术栈与合规约束

技术栈

  • LangChain：将 LLM 与七大工具箱组合
  • Profile / Holding / Recommendation / Allocation Tool：提供事实与计算
  • Redis：会话与跨会话记忆召回
  • MySQL、Neo4j、Milvus：存储业务事实、关系和知识上下文

合规约束

  • 适当性匹配：产品风险等级不能超过客户适当性范围
  • 风险预警联动：风险预警会收紧推荐范围与文案
  • 风险提示：配置输出保留风险提示和推荐依据
  • 反馈治理：拒绝反馈会影响后续偏好信号，但不会自动调整风险等级

六、总结与展望

从"经验推荐"到"证据推荐"

依托七大核心工具的原子化编排，顾问不再需要逐页翻阅产品手册。Agent 能够同时读取客户风险等级、持仓行业分布、产品适当性与知识上下文，输出的不仅有"推荐什么"，更保留了"为什么适配、受什么约束、风险在哪里"的完整逻辑链路。

坚守合规底线，实现"双重保护"

我们将合规要求深度内化为系统能力。通过"注册后风评弹窗与默认 R1 推荐"以及"风险等级自动降级"两大工程亮点，系统能够用客观的交易行为数据纠偏主观画像，确保在风评缺失或行为异常时，依然能守住适当性底线，实现从"事后抽检"到"实时伴随"的合规守护。

夯实底层基建，保障数据一致

针对金融级数据要求，我们设计了"Neo4j 同步失败自动重试机制"，通过异步非阻塞与兜底重试策略，彻底解决了复杂图谱数据同步的痛点，确保每一次"千人千面"的推荐都建立在绝对准确的数据基石之上。

严守业务边界，投顾不越权

AdvisorAgent 始终定位为"辅助决策工具"而非"投资顾问"。它不直接执行交易，也不修改正式风险评级，仅输出被画像、适当性和预警约束的可解释建议。真正的交易与评级，依然由受控的业务操作链路和正式审计流程来完成，确保 AI 赋能下的金融服务安全、稳健、合规。
