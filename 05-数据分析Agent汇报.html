一句结论

让业务人员用自然语言看数据，同时把 SQL 风险锁在系统之外

`NL2SQLService` 使用动态 Schema、Few-shot 示例和 LLM 生成查询；真正执行前必须通过只读 SQL 校验，并限制结果行数与表范围。

自然语言问题“资产超百万客户有多少？”
→
Schema 选择关键词匹配相关业务表 + Few-shot
→
生成 SQLLLM 只生成查询草案
→
SELECT 校验拦截 DELETE / UPDATE / INSERT / DDL
→
受限执行白名单表、最多 100 行
→
解释与洞察结果表格、图表、合格信号

当前实现：分析结果返回 SQL、数据和解释；只有客户、时间、数值与证据完整的结构化洞察才应进入 Agent 联动。

安全设计

  • SQL 必须以 SELECT 开头
  • 危险关键词以单词边界拦截
  • 业务表范围可控，避免暴露系统元数据
  • 最大返回 100 行，降低误操作与超大结果风险
策略约束

洞察不是“自动决策”

例如回撤或高频交易可形成可解释的策略信号，供投顾、风控和画像分别消费；不完整或非结构化结果不得发布事件，更不直接调高/调低正式风险等级。

输入：自然语言；输出：只读 SQL、结果、解释、受控洞察多 Agent 联动与架构 →
