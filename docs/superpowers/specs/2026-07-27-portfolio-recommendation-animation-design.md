# 持仓收益与产品推荐动画流程图设计

## 目标

新建独立的单文件 HTML 页面，用可播放的分层流程图演示金融智能助手如何处理问题：

> 我目前持仓收益率如何？给我推荐收益率高的产品。

页面服务于答辩投屏：在一条连续链路中解释请求编排、事实数据计算、Multi-Agent 协作、推荐决策、合规约束、流式响应和事件回写。它不发起真实交易，也不把“高收益”表达为承诺收益。

## 文件与展示风格

- 新文件：`持仓收益与推荐-动画流程图.html`。
- 单文件 HTML，内嵌 CSS 和 JavaScript，不依赖网络或第三方库。
- 延续 `记忆架构-动画流程图.html` 的浅色金融科技风格、SVG 节点图、路径播放器和可读性策略。
- 桌面投屏优先；小屏允许横向浏览复杂图谱。
- 支持 `prefers-reduced-motion`：关闭自动播放，仅保留手动逐步讲解。

## 页面构成

1. 标题和结论：收益分析以业务事实为准，产品推荐在适当性和风险约束内排序。
2. 场景提示：展示用户问题及模拟的客户上下文（持仓、风险等级、投资目标），明确这是演示数据。
3. 控制区：播放/暂停、上一步、下一步、重播、速度切换和步骤状态。
4. 主流程图：按七条泳道展示端到端业务闭环。
5. 单步讲解面板：显示本步工作内容、输入、输出、数据来源和合规边界。
6. 结果摘要卡：在结果节点展示持仓收益率、组合回撤、候选产品、推荐分数和风险揭示的模拟结果。
7. 规则说明区：说明高收益仅作为排序维度，风险/适当性过滤优先于收益排序。

## 七层端到端链路

### 1. 入口与安全边界

用户或理财顾问提出“查看持仓收益并推荐高收益产品” → 统一登录认证 → 身份、角色、客户归属与会话校验 → InputSafetyFilter → Chat Orchestrator。

所有后续查询带上 `customer_id`、`actor_id`、角色和会话范围；跨客户数据、未授权员工和不合规输入不可进入 Agent 或数据层。

### 2. 会话、实体与意图编排

MemoryManager 读取会话上下文；EntityTracker 提取客户、持仓、收益率、推荐数量等实体；IntentService/RouterAgent 将请求拆为“持仓收益分析”和“产品推荐”两个受控子任务，并建立 RoutePlan。

### 3. 持仓收益事实计算

HoldingTool 从 MySQL 的持仓、产品与交易流水读取份额、持仓成本、当前净值和交易记录，计算单品收益率、累计收益、组合收益率与最大回撤。MySQL 是收益计算和交易数据的权威事实源；Redis 只可加速读取，不可反向改写事实。

### 4. 客户约束与关系/知识增强

ProfileAgent 读取客户 C1-C5 风险等级、投资期限、流动性偏好和动态风险约束；GraphTool/Neo4j 计算行业集中度、已有产品重合和组合互补性；NL2SQL Agent 执行已校验的聚合查询；RAG 通过 Milvus + MinIO 检索产品说明、业绩口径与风险揭示原文。

### 5. 推荐与合规决策

AdvisorAgent 将收益分析、客户约束与候选产品交给 RecommendationTool。工具依次执行产品状态、风险等级、适当性、额度/集中度和动态风险过滤；仅在候选集内按风险匹配、偏好契合、组合互补性和历史收益表现排序。RiskMonitor 复核回撤、集中度和预警约束。

“高收益”不是唯一或优先于风险的标准；历史业绩不构成未来收益承诺。被过滤产品必须展示过滤原因，而非静默消失。

### 6. 受控响应与 SSE 返回

ExplanationAgent 生成持仓收益解读和候选产品的匹配理由；OutputSafetyFilter 移除保证收益或诱导性表述，补充历史业绩、净值波动、适当性和风险揭示；ResponseEnhancer 汇总为结果卡，经 SSE 流式返回。

### 7. 事件回写与可观测性闭环

用户查看、收藏、追问或明确反馈后，事件与审计记录同业务事实写入 MySQL/Outbox；Outbox Relay 可靠发布；Redis Pub/Sub 通知 ProfileAgent 刷新偏好投影、Neo4j 更新客户—产品关系、Redis 刷新会话/画像缓存；TraceService 记录链路、耗时与结果版本。反馈仅形成偏好或服务信号，不自动改变正式 C1-C5 风险等级。

## 播放步骤

主路径共 18 步，按以下顺序高亮：

1. 用户问题进入统一入口
2. 认证、RBAC 和客户归属校验
3. 输入安全过滤
4. 会话记忆、实体提取和复合意图路由
5. HoldingTool 读取持仓、交易与净值事实
6. 计算单品/组合收益率和最大回撤
7. ProfileAgent 读取客户风险等级与目标约束
8. GraphTool 分析行业集中度和持仓重合
9. NL2SQL 执行受控聚合查询
10. RAG 检索产品材料、业绩口径和风险揭示
11. RecommendationTool 构建候选产品池
12. 适当性、产品状态、动态风险和集中度过滤
13. AdvisorAgent 对可推荐产品排序
14. RiskMonitor 复核推荐组合
15. ExplanationAgent 和 OutputSafetyFilter 生成受控解释
16. ResponseEnhancer 组织结果，SSE 流式返回
17. 用户行为形成审计与 Outbox 事件
18. 订阅端刷新画像/图谱/缓存，并由 TraceService 完成观测闭环

## 交互规则

- 自动播放默认每步 1.6 秒，可选 0.8、1.6、2.6 秒。
- 当前节点和进入连线使用高强度动态高亮；历史节点保持低强度完成态。
- 点击当前路径中的节点跳转至该步；路线外节点降级显示。
- 切换步骤时同步更新讲解面板、模拟结果卡和答辩提示。
- 自动播放结束停在闭环节点；重播回到第一步。

## 验证

- 以 UTF-8 读取页面，检查标题、18 步数组、播放器控件、SSE、Outbox、HoldingTool、RecommendationTool、OutputSafetyFilter 和五类数据基础设施术语。
- 使用浏览器打开页面，检查首屏布局、横向 SVG 图谱、节点高亮、路径播放、手动跳转和减少动效模式。
- 不改动后端服务、数据库、真实交易或现有“记忆架构”页面。

## 自检

- 页面范围仅为答辩展示，不伪造真实收益或收益承诺。
- 所有收益计算均以 MySQL 事实为准，缓存和图谱仅用于加速或解释。
- 推荐排序位于适当性和风险过滤之后，符合金融合规边界。
- 行为回写采用 Outbox + 消费投影，不使缓存或模型推断覆盖正式风险评级。
