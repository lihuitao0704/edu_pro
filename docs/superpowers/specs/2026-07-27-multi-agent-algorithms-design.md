# 多 Agent 汇报页算法决策章节设计

## 目标

在 `06-多Agent联动与架构汇报.html` 的 14 个业务场景之后、需求映射之前增加“算法驱动的智能决策”章节。该章节以六张算法卡片说明画像更新、客群分层、候选召回、排序、图谱关联和异常检测如何支撑 Multi-Agent 协作。

## 页面位置与表现

- 插入位置：场景 14 后的 `</section>` 与“从需求分阶段到金融级协同”标题之间。
- 使用既有 `grid three` 和 `card` 样式，分两行展示六张卡片。
- 章节开头提供总原则：先由权限、适当性、产品状态、风险和集中度构成合规候选池，再由模型完成分层、召回、解释或排序。
- 每张卡片统一包含“算法 / 输入与机制 / 业务作用 / 合规边界”四部分，保证答辩表达可比较、可连续讲解。

## 六项算法文案与边界

### 1. 贝叶斯更新：动态用户画像

以“稳健 60%、积极 40%”作为先验偏好；在连续、有效的权益类交易证据出现后，根据证据权重更新为“稳健 40%、积极 60%”。输出是动态偏好概率与置信度，用于调整沟通和候选权重；不自动修改正式 C1-C5 风险等级。

### 2. GMM：无监督用户分层

使用资产规模、风险承受能力、交易频率、产品复杂度、投资期限和偏好等特征，以高斯混合模型形成稳健型、高净值进取型、投资新手等客群。输出用于分层服务、产品匹配和合规运营触达，不以聚类标签替代风险测评或产品适当性结论。

### 3. UserCF：协同过滤候选召回

从风险边界和行为特征相近的用户群中发现“喜欢 A 产品的相似用户也认可 B 产品”的关联，把 B 纳入候选参考。协同过滤只扩展候选池，候选仍须接受产品状态、风险等级、适当性和集中度筛选。

### 4. LightGBM Rank：Learning-to-Rank 排序

在合规候选池内，将风险匹配、投资期限、流动性、偏好、组合互补性和历史表现作为特征，由 LightGBM 的排序目标计算匹配度并输出 Top N。模型不对不合规产品排序，也不得用历史表现承诺未来收益。

### 5. 知识图谱 Agent：关系发现与可解释扩展

基于客户—基金—行业—主题关系与图算法识别偏好；例如发现客户偏好新能源基金后，扩展检索新能源产业链中的合规候选产品，并返回路径依据。图谱用于关系解释和候选扩展，不作为交易结算或正式评级依据。

### 6. Isolation Forest：异常交易检测

学习客户常态交易金额、频次、产品类型和时点；例如平时购买基金的客户单日买入 500 万股票，模型给出 92% 异常概率时，触发人工审核、资金保护或风险提示。异常分数是预警信号，不自动拒绝交易或改变正式风险等级。

## 自检

- “精准营销”被表述为分层服务、产品匹配和合规运营触达，避免将模型分层描述为无约束营销。
- 贝叶斯更新、协同过滤、图谱和异常检测均为辅助信号；正式 C1-C5、适当性和交易审核仍由受控规则/流程决定。
- 收益相关排序限定在合规候选池，历史表现不构成未来收益承诺。
