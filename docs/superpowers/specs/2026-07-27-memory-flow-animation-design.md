# 记忆架构动画流程图设计

## 目标

新建一个独立 HTML 页面，以逐节点播放方式展示当前项目的金融级记忆架构。页面用于答辩投屏，清晰演示读取路径、事件写入路径、五类记忆与金融数据权威边界。

## 文件与风格

- 新文件：`记忆架构-动画流程图.html`。
- 单文件 HTML，内嵌 CSS 和 JavaScript，不依赖网络或第三方库。
- 浅色、低饱和金融科技风格；桌面端以宽屏流程图为主，移动端允许横向查看图谱。
- 支持 `prefers-reduced-motion`，减少动效偏好下保留手动逐步查看能力。

## 页面构成

1. 标题和简短答辩结论：记忆是受权限、时效与事实约束的决策上下文。
2. 控制区：读取路径 / 写入路径切换，播放、暂停、上一步、下一步、重播按钮和速度选择。
3. 主流程图：
   - 读取路径：用户请求 → Chat Orchestrator / Router → Memory Manager → Redis 会话与路由上下文 → Redis 画像与风险投影 → MySQL 业务事实 → Milvus + MinIO 知识证据 → Neo4j 关系解释 → Agent 受控响应。
   - 写入路径：交易或业务事实 → MySQL 事务 + Outbox → Outbox Relay → Redis Pub/Sub → 画像缓存失效 / 风险投影 / Neo4j 图谱同步 / 审计归档 → 下一次 Memory Manager 读取。
4. 单步说明面板：当前节点、读取/写入对象、权威性、权限/合规边界。
5. 记忆矩阵：Redis、MySQL、Milvus、MinIO、Neo4j 的职责与非职责。

## 动效规则

- 每次只高亮当前节点和进入该节点的连线；已完成节点维持低强度高亮。
- 自动播放每步间隔 1.6 秒，速度可切换为 0.8 / 1.6 / 2.6 秒。
- 用户切换路径、点击上一步/下一步或重播时，立即更新主图和说明面板。
- 不使用装饰性连续动画；动效仅表达数据流转和当前讲解位置。

## 事实与合规边界

- MySQL 是交易、持仓、正式画像、审计和 Outbox 的业务事实源。
- Redis 是会话/上下文与可失效缓存投影，不反向覆盖事实。
- Milvus/MinIO 提供可追溯知识检索证据；Neo4j 是可重建的关系投影。
- 任意检索、缓存、事件或模型推断均不直接修改正式 C1-C5 风险评级或绕过交易确认。

## 验证

在 `tests/test_report_html.py` 中验证新页面含两条路径、五类存储、播放器控制、步骤数据、MySQL 事实源和减少动效支持；通过完整静态报告测试。

## 自检

页面不修改既有记忆架构汇报，也不改动后端服务；动画仅呈现已有架构事实与边界。节点名称、流转顺序和存储职责均与 `07-记忆架构汇报.html` 保持一致。
