# 统一前端启动与 AI 财富助手体验设计

## 目标

让 `python main.py` 成为唯一生产启动入口；前端页面和后端 API 使用同一端口，并保证顾问工作台推荐、客户画像、LLM 说明和 AI 财富助手的核心体验可用、可验证。

## 范围

包含：

- 前端构建、静态资源托管和端口选择。
- 顾问工作台的“生成推荐方案”数据链路、LLM 说明和风险提示。
- AI 财富助手的意图识别、低置信度澄清和统一的交互状态。
- 前端页面关键 API 的可用性测试与构建修复。

不包含：

- 对数据库业务数据或既有六 Agent 业务规则的重构。
- 新增外部基础设施或替换模型供应商。

## 启动与端口

1. `main.py` 在启动前确保 `frontend/dist/index.html` 存在；缺失时调用项目配置的包管理器构建前端，构建失败时输出可行动错误并不启动一个会返回空页面的服务。
2. FastAPI 继续托管 `frontend/dist`、`/assets`、Vue history fallback 和 `/api/*`，因此生产浏览器只使用一个 origin。
3. 启动优先选择 8000。仅当监听进程可识别为当前工作区启动的 Python/Uvicorn 进程时才结束它；不终止未知进程。
4. 若 8000 在检查后仍不可绑定，自动使用 8001，并在启动日志中打印完整访问地址。前端 API 使用相对路径 `/api`，无需额外代理或端口配置。
5. Vite 5173 只保留为前端独立开发命令，不作为 `main.py` 的运行依赖。

## 顾问推荐链路

1. 顾问工作台直接调用投顾 API，不经统一聊天路由再次进行意图分发。
2. `smart_recommend` 不能把同一个 `AsyncSession` 并发交给画像和配置查询。它先读取客户画像，再以同一份有效画像生成推荐和配置，消除“页面显示画像失败、结果却显示 C3”的矛盾状态。
3. 后端返回结构化字段 `customer_profile`、`recommendations`、`allocation`，并同时返回 `narrative` 和 `narrative_source`：
   - LLM 成功时，`narrative_source=llm`；
   - LLM 超时/失败时，`narrative_source=template`，但仍返回完整且友好的说明。
4. 只在画像确实不存在或查询真实失败时展示状态提示；画像正常时不允许生成“暂时无法获取”的文案。
5. 所有含推荐的输出，无论来自 LLM 还是模板，均在末尾追加固定合规提示：投资有风险，入市需谨慎；不构成投资建议。

## AI 财富助手体验

1. 统一聊天入口使用三层意图识别：明确关键词和上下文规则优先；规则不确定时调用现有 LLM 分类；置信度不足时不臆测业务操作，而是返回一条简短澄清问题及可选示例。
2. 消息响应携带 `intent`、`confidence`、`agent`、`reply`、结构化数据和会话 ID；前端按照这些字段展示，而不直接输出原始 JSON。
3. 前端在发送期间禁用重复提交、显示进行中的状态；失败时展示友好可重试错误；流式响应和普通响应复用同一消息状态机。
4. 不暴露内部异常、SQL、栈信息或模型调用错误。

## 验证标准

- `python main.py` 可启动：8000 可用时访问 `http://127.0.0.1:8000`；否则访问 `http://127.0.0.1:8001`。
- 前端构建无 TypeScript 错误。
- 有画像客户请求推荐时，结构化画像与推荐风险等级一致，且不显示画像失败提示。
- 推荐回复包含 LLM 或受控模板说明，且始终包含风险提示。
- 顾问工作台、客户画像、持仓分析、风险管理、业务操作、知识库和 AI 财富助手的关键 API 至少各有一条前端/API 冒烟验证。
- 意图识别对客服、投顾、风控、数据分析、业务操作的典型问法能稳定路由；不确定问法返回澄清而非错误路由。
