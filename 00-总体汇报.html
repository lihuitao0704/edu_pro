业务结论

把财富服务的“判断、建议、执行、守护”串成可控闭环

平台以统一对话入口承接多角色需求，Router 与编排层将请求分派给六类 Agent；规则、数据与知识底座保证业务过程可解释、可审计、可持续演进。

6 类

专业 Agent

客服、画像、投顾、风控、数据分析、业务操作在统一口径下协作。

5 类

数据与知识基础设施

业务事实、会话缓存、关系推理、语义检索与文件知识各司其职。

1 条

统一服务链路

HTTP/SSE 请求经 API、路由与编排，交付结构化、可追溯的结果。

项目主流程

Vue 3 前端客户对话、顾问工作台、风控与运营页面
→
FastAPI统一 API、身份边界、HTTP / SSE
→
Router + 编排六类意图识别、风险预检、统一响应
→
业务 Agent客服 / 画像 / 投顾 / 风控 / 分析 / 操作
→
服务与底座规则、工具、MySQL、Redis、Neo4j、Milvus、MinIO

当前实现：`main.py` 提供入口；`unified_chat.py` 与 Router/ChatOrchestrator 统一承接自然语言服务。

技术栈：为什么这样组合

应用与智能层

  • Python + FastAPI：异步 API 与 SSE 流式反馈
  • SQLAlchemy Async：业务数据访问
  • LangChain + OpenAI 兼容 SDK：工具调用和模型编排
  • Pydantic：输入输出契约与参数校验

体验与数据层

  • Vue 3 + TypeScript + Vite：企业级交互界面
  • Pinia、Element Plus、ECharts：状态、组件和看板
  • MySQL / Redis：事实数据、缓存和会话
  • Neo4j / Milvus / MinIO：关系、语义和文档知识

六类 Agent 的分工

客服 / 画像

回答与理解客户；沉淀画像、偏好与短期行为信号。

投顾 / 风控

在适当性约束内生成建议；通过规则、预警和工单守住边界。

操作 / 分析

把自然语言转为受控业务办理或只读数据洞察。

总结：AI 负责理解与编排，规则负责确定性约束，数据底座负责事实与记忆——三者共同构成金融服务的可信闭环。
